### T3 (COMPLETED)

> Account opening was failing with timeouts on 15 October 2026 around lunchtime. Investigate.

Root cause: The NSDL PAN verification API became unresponsive, causing the pan‑verification‑gateway to time out and downstream account‑service requests to fail (including DB connection pool timeouts).



Evidence:

- **PAN_TIMEOUT failures**: 64 occurrences in the 12:00‑17:00 window (application stats).

- **pan‑verification‑gateway errors**: 161 ERROR logs “NSDL PAN API call timed out…” from 14:00 to 14:40 UTC.

- **account‑service errors**: 161 ERROR logs “HikariPool‑N – Connection is not available, request timed out…” from 12:30 to 13:10 UTC, coinciding with the surge of failed PAN checks.

- No deployments of `pan-verification-gateway` or `account-service` around the incident time, ruling out a code change.



Impact:

- All customers attempting to open an account during the lunch period (12:00‑17:00 UTC) experienced failures.

- Approximately 120 applications per hour, with 38 – 66 not approved each hour; the majority were due to PAN_TIMEOUT and generic TIMEOUT errors.



Suggested fix:

- Implement a circuit‑breaker and exponential back‑off for calls to the NSDL API in the pan‑verification‑gateway, and increase the DB connection pool size or tune timeout settings in account‑service to handle the retry load. Additionally, set up alerting on external PAN API latency to detect similar outages early.

### T4 (COMPLETED)

> Between 12:30 and 13:10 UTC on 15 October 2026 many account applications failed with timeouts. Find the cause.

Root cause: An ad‑hoc reconciliation batch job that performed a full scan of the account_applications table started at 12:28 UTC and exhausted the HikariCP connection pool, causing subsequent account‑service requests to time out.



Evidence:  

- [ERROR] account-service ×161 (12:30‑13:10) – “Connection is not available, request timed out …”  

- [WARN] account-service ×1 (12:29) – “Slow query on account_applications took N.Ns”  

- [INFO] account-service ×1 (12:28) – “Started ad‑hoc reconciliation batch job (full scan of account_applications)”  

- No deployments of account‑service in the window, ruling out code changes.



Impact: 48 account‑opening applications failed with TIMEOUT errors (36 not approved) between 12:30 and 13:10 UTC on 15 Oct 2026.



Suggested fix: Reschedule or throttle the reconciliation batch (run it during off‑peak hours or limit its DB connection usage) and/or increase the HikariCP pool size to handle concurrent traffic.
